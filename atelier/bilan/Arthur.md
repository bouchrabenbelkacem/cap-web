# Bilan individuel · Arthur

## Mon niveau de départ

Mardi matin, HTML, CSS, le DOM et Git, ça allait. JavaScript et les tests, beaucoup moins : je voyais à peu près ce qu'il fallait faire, mais dès que j'étais seul devant le code, je bloquais. Je voulais surtout sortir de ces deux jours capable de m'en sortir sans tout demander.

## Deux acquis

- **Savoir quoi faire quand un test est rouge.** 
Au début, je lançais les tests, je voyais du rouge, et je ne savais pas par où commencer.
Maintenant je lis le message, je cherche la cause, et je corrige.
Ça m'a servi dès le round 1, sur les messages vides et la limite
(`6ba515a`, `8cbda73`). Le moment où ça a vraiment cliqué, c'est le round 3 : j'ai écrit le test d'abord, je l'ai vu échouer, puis j'ai
écrit le code (`707464c`). Le soir, je me sentais nettement plus à l'aise qu'au réveil. À J3, j'ai encore galéré un peu avec le lint, mais j'ai fini par le débloquer (`76b47fe`).

- **Faire avancer une vraie petite appli, pas juste un exerciceisolé.** 
En deux jours, Cap Web a changé sous mes mains : un mot en plus (`4859ff4`), le compteur (`35a57dc`), l'affichage sur téléphone (`5a72fa4`), une route serveur (`20b877a`). Je comprends mieux qui fait quoi entre la page et le serveur. On a aussi chacun travaillé sur une branche, ouvert une pull request (`7a323c6`) et lu celle de l'autre (`4e31009`). C'est la première fois que je fais ça pour de vrai, à deux, sur GitHub.

## Deux points à renforcer

- Je veux écrire plus de JavaScript sans recopier un exemple à côté,
  surtout quand une requête peut rater.
- Je veux être plus à l'aise pour récupérer le travail de l'autre
  avant d'envoyer le mien : aujourd'hui un `pull` mal placé m'a coincé,
  et le `push` a été refusé.

## Mon objectif

Pour le prochain projet, je veux poser un test tout seul, le faire
passer, et arriver à le pousser sur GitHub sans bloquer le binôme.
